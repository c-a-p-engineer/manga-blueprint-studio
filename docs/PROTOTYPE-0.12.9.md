# Prototype 0.12.9 — producer provenance and current-state synchronization

Prototype 0.12.9 closes a debugging gap found during real ChatGPT/Gemini handoff testing: an exported ZIP could be generated by an older GitHub Pages deployment while the repository `master` already contained newer handoff hardening, and the ZIP itself did not identify which application build produced it.

## Shipped

### Export producer provenance

Every newly exported manifest records a `producer` object containing:

- producer schema;
- application version;
- deployed Git commit when available;
- build source;
- deployment timestamp when available;
- project-format, manifest-schema, and render-brief schema identifiers.

This metadata is diagnostic only. It does not change project-state hashing or character/page semantics.

### GitHub Pages build stamping

`web/build-info.json` is a repository/local fallback. The Pages deployment workflow overwrites the deployed copy with the exact `GITHUB_SHA`, `buildSource: github-pages`, and deployment timestamp before the static artifact is uploaded.

`web/app.js` fetches that file with `cache: no-store` before runtime chunks load and exposes the resolved build through `globalThis.MANGA_BLUEPRINT_BUILD_INFO`.

A local static server therefore remains zero-build and functional, while deployed exports can identify the exact source revision that produced them.

### Documentation status

README and Roadmap now identify Prototype 0.12.9 as the current implementation baseline. Older `Prototype 0.x` labels inside feature-history documents describe the release where a capability was introduced; they are not the current application version.

## Compatibility

- project format remains `manga-blueprint/0.2`;
- manifest remains `manga-blueprint-export-manifest/3`;
- render brief remains `manga-blueprint-render-brief/1`;
- build metadata is additive and does not change serialized project-state identity;
- local/offline use falls back safely when deployment provenance is unavailable.

## Debugging use

When a generated result appears inconsistent with current repository behavior, inspect `*_manifest.json` first:

```json
{
  "producer": {
    "schema": "manga-blueprint-producer/1",
    "appVersion": "0.12.9",
    "gitCommit": "<deployed commit or null>",
    "buildSource": "github-pages",
    "deployedAt": "<ISO timestamp>",
    "projectFormat": "manga-blueprint/0.2",
    "manifestSchema": "manga-blueprint-export-manifest/3",
    "renderBriefSchema": "manga-blueprint-render-brief/1"
  }
}
```

A missing `producer`, an older `appVersion`, or an unexpected commit is evidence that the export came from an older/stale runtime rather than the current application contract.
