HUMAN-DIRECTED MANGA BLUEPRINT

漫画の「どう見せたいか」を、
画像生成の前に決める。

人が監督。AIは補助。 Story Template や Smart Manga が提案しても、最終的な設計はいつでも編集できます。

WHY

「いい感じの漫画にして」だけでは、演出が消える。

画像生成AIに一枚絵の指示だけを渡すと、コマの役割、読み順、視点、人物の位置関係、表示してよい文字などが曖昧になります。Manga Blueprint Studio は、それらを生成前の設計情報として保持します。

FEATURES

漫画を作る順番に沿って設計する

機能一覧ではなく、「作品 → ページ → コマ → AIへ渡す」という制作の流れを中心にしています。

01

作品とページを整理

複数作品と複数ページをブラウザ内に保存。P001 形式で移動し、必要なら巻・章・フォルダも使えます。

02

漫画らしいコマを組む

通常の矩形だけでなく斜めコマ、四隅編集、小窓コマ、断ち切り、ブチ抜きまでページ上の構図として扱います。

03

演出意図を残す

人物、ポーズ、表情、視線、カメラ、背景、吹き出し、SFX、効果線などを、絵とは別の意味情報として保持します。

04

AIへ安全に渡す

クリーンPNG、プロジェクトJSON、Prompt、read-first manifest をまとめ、制作メタ文字を完成絵へ混入させない境界を作ります。

WORKFLOW

最短4ステップ

  1. 1
    作品を開く

    新規作品を作るか、保存済み作品を選びます。

  2. 2
    ページを作る

    原稿サイズと読み方向を決め、Story Template または手動でコマ割りを作ります。

  3. 3
    コマを演出する

    人物・カメラ・背景・文字・効果を選択中のコマへ設定します。

  4. 4
    AI生成ZIPを書き出す

    選択中の1ページを、画像生成へ渡せるパッケージとして出力します。

AI HANDOFF

一枚のPNGに全部を背負わせない

空間、意味、人物、画風、文字を別の責務として渡すことで、画像生成側が読み違えにくい構造にします。

DESIGN PRINCIPLES

補助機能が勝手に漫画を決めない

Human directed

Story Template と Smart Manga は候補を出します。適用するまで作品状態は変わりません。

Local first

作品データは IndexedDB に保存。外部AIへ渡す内容は、ユーザーが書き出す生成パッケージで明示します。

Provider independent

コアの作品データを特定の画像生成サービス専用にせず、下流モデルへのハンドオフ境界を分離します。

CURRENT SCOPE

いま出来ることを、過剰に見せない。

現在のAI生成パッケージは選択中の1ページ単位です。複数ページ一括書き出し、完全なバックアップ/復元、最終画像への決定論的な文字組みなどは今後の対象です。
